Why Arken Auth

Your server stores nothing sensitive

Traditional auth makes you responsible for secrets. Arken flips the model — users hold their keys, you verify proofs.

🔑

No passwords

Users authenticate with a cryptographic signature. There's no password to store, hash, or reset.

♻️

No sessions

Every request is independently verifiable. No JWT refresh cycles, no session store, no expiry headaches.

🛡️

Nothing to breach

A stolen database of DID strings is a contact list. There are no hashed passwords, no tokens to rotate.

⚡

Drop-in middleware

One function call protects a route. No configuration, no app registration, no OAuth dance.

🌐

No third-party dependency

No "Sign in with Google." Your auth doesn't break when another company changes their API.

📦

GDPR-friendly by default

You never hold PII you didn't ask for. No consent flows for data you don't store.

How it works

Challenge-response, cryptographically

The server issues a random nonce. The client signs it with their private key. The server verifies the signature. No shared secret ever exists.

The private key never leaves the user's device. Your server sees a DID (a public identifier) and a signature. If the signature matches the DID's public key, the user is authenticated.

flow 
→ GET /protected

← 401 + { challenge: { nonce: "a7b3..." } }

  client signs nonce with private key

→ GET /protected
  Authorization: Signature
    did="did:key:z...",
    nonce="a7b3...",
    signature="0x9f2..."

  server recovers signer from signature
  checks: recovered address == DID key?

← 200 OK
Quickstart

From zero to protected in 5 minutes

You need Node.js and Rust installed. Rust is used to compile the cryptographic core — you don't write any Rust.

Install Rust (if you don't have it)

One command. Takes about 2 minutes.

$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Install arken-auth

The postinstall script compiles the Rust core for your platform automatically.

$ npm install arken-auth

Protect a route

Add one middleware call. That's it.

const express = require('express');
const { arkenAuth } = require('arken-auth');

const app = express();

app.get('/orders', arkenAuth(), (req, res) => {
  res.json({ user: req.user.did });
});

Authenticate from the client

Any wallet that can sign an Ethereum message works. Here's a minimal example with ethers.js.

const { ethers } = require('ethers');
const bs58 = require('bs58');

// 1. Generate a DID from any wallet
const wallet = ethers.Wallet.createRandom();
const key = new ethers.utils.SigningKey(wallet.privateKey);
const bytes = Buffer.concat([
  Buffer.from([0xe7, 0x01]),
  Buffer.from(key.compressedPublicKey.slice(2), 'hex')
]);
const did = `did:key:z${bs58.encode(bytes)}`;

// 2. Get challenge, sign nonce, send
const { challenge } = await (await fetch('/orders')).json();
const sig = await wallet.signMessage(
  ethers.utils.toUtf8Bytes(challenge.nonce)
);
const res = await fetch('/orders', {
  headers: {
    Authorization: `Signature did="${did}",nonce="${challenge.nonce}",signature="${sig}"`
  }
});
